# Локальная сверка Save Cash с ChatGPT

1. В настройках выберите **Экспорт данных для сверки с ChatGPT → Подготовить файл → Скачать файл**. Проверьте загрузки. Приложение само ничего не отправляет в ChatGPT.
2. Прикрепите JSON и банковские скриншоты к своему сообщению. Снимок содержит личные финансовые данные; оригиналы чеков и полные номера карт не включаются.
3. После проверки попросите подготовить отдельный JSON из `review_template` экспортированного файла. Сохраните его в UTF-8 с расширением `.json`.
4. В Save Cash: **Импорт сверки с банком → Выбрать файл сверки**. Сверьте обе стороны, изменения итогов и прогноз. Только **Подтвердить импорт** применяет изменения. Оригинал, решения и резервная копия сохраняются локально.

Изменение финансовых данных после экспорта делает снимок устаревшим. В этом случае нужен свежий экспорт. Повторно применить тот же результат нельзя. Это не банковское подключение и не автоматическая синхронизация.

## Формат результата

Корневые поля: `app: "Save Cash"`, `type: "save-cash-bank-review"`, `schema_version: 1`, уникальный `id`, исходные `snapshot_id` и `base_fingerprint`, массивы `card_totals` и `decisions`. Реальные ID и fingerprint берутся из свежего экспорта, не придумываются.

`card_totals`: `card_id`, `charge_date` (YYYY-MM-DD), `before_amount` (старый банковский итог), `amount` (новый банковский итог). Суммы — JSON-числа с точкой, в шекелях. Операции вне итога в `amount` не добавлять: приложение добавит их отдельно.

Каждая строка `decisions`:

- `id`: уникальный ID решения.
- `left_id`: ID первичной записи из `source_ref`/журнала, например `purchases:<id>`, либо `null`. Для изменения уже импортированной банковской строки допустим `cardBankOperations:<id>`.
- `right`: `id` (постоянный ID банковской строки), `card_id` (ID из `cards`, не полный номер карты), `name`, `amount`, `currency: "ILS"`, `operation_date`, `charge_date`, `bank_status`; при наличии — `transaction_id` банка.
- `status`: `совпало`, `ожидает банк`, `разница` или `спорно`.
- `choice`: `left`, `right` или `defer`. `left` требует существующей записи. `defer` требует `status: "спорно"` и `bank_status: "disputed"`.

Банковские статусы:

| bank_status | Смысл | Вклад |
| --- | --- | --- |
| pending | Ожидает включения в банковский итог | Отдельно сверх итога |
| included | Уже в банковском итоге | Дополнительно 0 |
| posted | Проведена по карте, ещё вне итога | Отдельно сверх итога |
| disputed | Существенное расхождение не решено | Сохраняется для проверки; не создаёт вымышленную подтверждённую нагрузку |

«Проведена по карте» не означает «списана с дебетового счёта». Подтверждённый остаток банка этот импорт не заменяет. При переносе операций в банковский итог обновляйте `card_totals.amount` и статусы `included` в одном файле. Сумма итога не является потолком для новых операций.

Для повторного уточнения используйте новый экспорт и новый ID сверки; ID существующих банковских строк сохраняйте. Одинаковые суммы сами по себе не доказывают совпадение. Неоднозначные строки оставляйте спорными либо явно выбирайте правильный `left_id` после проверки. Откат состояния доступен через восстановление полной резервной копии, сохранённой до импорта; история импортов не удаляется при обычном обновлении PWA.
